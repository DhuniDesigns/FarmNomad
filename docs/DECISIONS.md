### Technical — first real boot against a migrated database (2026-08-04)
| Decision | Rationale | Rejected alternative |
|---|---|---|
| `User.email` given an explicit `@Column(columnDefinition = "citext")` | `spring.jpa.hibernate.ddl-auto: validate` failed app boot with `SchemaManagementException: wrong column type encountered in column [email] in table [users]; found [citext (Types#OTHER)], but expecting [varchar(255) (Types#VARCHAR)]`. The `users` table's `email` column has always been Postgres `citext` (V1__init_users.sql); the entity mapped it as a bare `String` on the assumption that Java-level case-insensitivity didn't matter since Postgres handles it — true for reads/writes, but `ddl-auto: validate` checks the JDBC-reported column type at boot regardless, and `citext` isn't a type Hibernate recognizes as compatible with plain `varchar`.
